# Benchmarks

Public material the runtime is measured on, apart from the gates under
`docs/gates`, which use the first consumer's private recordings. A
benchmark here is reproducible by anyone with the dataset and a stock
Vosk model; each page names the script, the grammar and the figures.

General word-error benchmarks (LibriSpeech, TED-LIUM, Common Voice) do
not apply: the runtime decodes under a grammar only, by
`[[rr:TD-2#Scope]]`. Closed-vocabulary sets do.

| Page | Dataset | What it measures |
|---|---|---|
| `speech-commands.md` | Google Speech Commands v2 | accuracy under a command grammar with distractors, agreement with the oracle, determinism, first-appearance and endpoint latency, block size, compute, accuracy against noise, the cost of grammar size, the unknown-word symbol and silence |
| `partial-trust.md` | Google Speech Commands v2 | whether a partial word will hold: the gap to the next reading as a calibrated probability, against the word's own confidence, its energy, the entropy of the readings, and the motion of each reading's lead between decoding advances, with every rule fitted on the validation split and charged in milliseconds of delay; beside them the merge-loss figure, how often a reading still in contention is gone by the next advance and whether those clips revise more |
| `partial-states.md` | Google Speech Commands v2, built into streams | what the readings say about silence and about the word after this one: the trailing silence entry against the beam's motion as an end-of-speech signal, the preview an extending reading gives, and, exploratory, whether anything calls a word before it is spoken |

Each page is generated by its script and then read. Beside a page the
script leaves `<page>.json`, every figure in machine form, and
`<page>.clips.jsonl`, one line per clip with each engine's reading, so
two runs can be diffed to the clip rather than compared as totals. A
page opens with the revision, engine versions and machine it was run
on, without which the compute figures say nothing.

The page itself is overwritten by every run, so what a run *means* is
written in `<page>.reading.md` and the report appends it to itself. The
prose is kept under version control beside the figures and survives
being regenerated.

Where the two engines are compared, the comparison is paired: the same
clips through both, and the split reported with an exact McNemar test,
because a difference of a handful of clips in ten thousand is otherwise
indistinguishable from chance.

Accuracy is not agreement. The runtime's contract is to reproduce
libvosk's output, and two engines are at parity on accuracy exactly
when they are right equally often, which says nothing about their
being right about the same clips. Every page that compares against the
oracle reports both, and reports empty finals split by direction,
because a one-way excess of them is what a decoder dropping a reading
looks like and no accuracy or latency figure shows it.

One page per model, not one page comparing models. The provenance
header binds a page's figures to a model, a build and a machine; the
paired tests compare two engines over one model's readings, and there
is no paired test across models, because the clips are decoded under
different acoustics and nothing links a clip's two readings. A page
per model also keeps each table narrow enough to read and keeps
`<page>.clips.jsonl` diffable against the same page from last week.
The script takes `--model` and writes wherever `--out` says, so a
second model is a second row in the table above and no change to the
script.

Compute figures that are not about a dataset live in `benches/`, which
`cargo bench --bench kernels` runs: the matrix kernel at the network's
real shapes and grammar composition against grammar size, reported as
the minimum over a pinnable number of repeats. Those are the figures
`[[rr:TD-3]]` and `[[rr:TD-5]]` quote, and they are there so that a
decision record's numbers can be re-run rather than taken on trust.
